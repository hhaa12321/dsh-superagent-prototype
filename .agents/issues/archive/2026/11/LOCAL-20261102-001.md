## Body

## Background / Problem
The `superagent` DSH profile has no `llm-pi-ai.providers` catalog, while `web` exposes the maintained `gpt-load` provider with 36 models. The superagent UI therefore cannot select the same provider/model set.

## Goal
Mirror the current `web` provider and model catalog into `superagent` without changing its default model, service identity, state, or repository execution settings.

## Acceptance Criteria
- [ ] `superagent/cordis.patch.yml` contains the same `llm-pi-ai.providers.gpt-load` definition and model list as `web`.
- [ ] `dsh --dump-config --profile superagent` resolves the provider and model block without configuration errors.
- [ ] The isolated `superagent` service restarts on port 3082 and reports ready.
- [ ] `web` process and config remain unchanged.

## Planned Validation
- Compare the generated provider block against `web` with dsh-model-sync diff.
- Parse both YAML files and compare provider/model counts and definitions.
- Dump the resolved superagent config and restart only the superagent service.
- Check service status, listener, and logs for reload/startup errors.

## Risks / Boundaries
- Do not change the superagent default model.
- Do not copy unrelated web bundles, plugins, settings, or environment.
- Do not stop or restart the web profile.
- Do not print or persist credential values.
