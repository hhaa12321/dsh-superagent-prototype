## Body

## Background / Problem
The upstream dsh-superagent prototype is buildable but models one GitHub repository as global deployment state. The fork must serve multiple repositories and support multiple Git providers, with Gitee as the first additional provider.

## Goal
Establish the fork baseline and document a concrete, source-grounded roadmap for multi-repository, multi-forge support without compatibility layers or migrations.

## Acceptance Criteria
- [ ] The local repository is the requested GitHub fork of deepseek-ai/dsh-superagent-prototype.
- [ ] The architecture and delivery roadmap identify the single-repository assumptions in the current code.
- [ ] The roadmap supports multiple repositories and multiple forge adapters, with Gitee delivered before a second additional forge.
- [ ] The first end-to-end slice is explicit, testable, and avoids temporary architecture.
- [ ] Existing project checks pass after the documentation change.

## Planned Validation
- Verify git remotes and fork relationship.
- Run pnpm check.
- Review the roadmap against the current source tree.

## Risks / Boundaries
- Do not implement Gitee or multi-repository behavior in this task.
- Do not add backward compatibility, migration logic, or fallback paths.
- Preserve the upstream prototype as a remote for future synchronization.

### Why this approach
- The prototype is not missing a repository list: repository identity is global across deployment, commands, Source registry/context, domain records, PR binding, worker tools, workspace, policy, and persistence.
- The roadmap uses one control plane with many explicit `RepositoryBinding` aggregates and multiple Source instances per kind. It rejects process-per-repository and provider conditionals in the Engine.
- The clean break uses a fresh state directory with no migration, compatibility layer, dual read path, or default-repository fallback.
- Gitee API v5 uses immutable native IDs while retaining display IDs. Polling is the first event source; webhooks are deferred until polling semantics are proven.
